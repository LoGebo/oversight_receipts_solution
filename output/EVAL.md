# Evaluation

Generated by `python -m validator.evaluation.evaluate` from the committed classifier cache (no model calls). 28 scored receipts / 65 scored lines (RCP-020, RCP-021, RCP-029, RCP-030 out of scope; all 32 run for group context). Classifier: openai/gpt-oss-safeguard-20b, prompt v3. Brackets: two-sided 95% Clopper-Pearson; `W[...]` Wilson; `boot[...]` percentile bootstrap, 10,000 receipt resamples, seed 20261026.

## How to read this

- **Tiny n, one run.** 28 receipts, 9 pass / 16 flag / 3 review. An interval spanning 30 points is the honest size of what we know. Per-class figures on the 3 review receipts are anecdotes, not rates. A bootstrap of a perfect score is degenerate (`boot[100%, 100%]`: every resample is perfect); for those, read the Clopper-Pearson bound.
- **Only the classifier is measured blind.** The rule engine was written with this dataset (and its answers) in view, so B ORACLE is a consistency check of the engine against the answers, not an estimate of how it generalises. A LLM is the only number where the measured component never saw the answers (prompt = taxonomy text only), and even there the taxonomy's own examples sit in the prompt.
- **The keyword baseline (C) was frozen before scoring** (sha256 of its table and compiled patterns pinned in tests). It feeds the same engine, so A vs C isolates the classifier; differences are measured on the same 28 receipts and are paired. C maps descriptions to all 21 categories (restricted words tried first), because the engine and macro F1 need a category, not just a yes/no.
- **The dataset is enriched:** 16/28 = 57.1% flag. The base-rate tables below are a what-if, not a measurement.
- The held-out stress test (last section) is a separate set written by a single annotator; its expected labels are one person's judgement.

## What each score says about whether the engine gets the inputs it needs

- **Macro F1 on categories** (A 0.965, C 0.776). The category is the input every category-keyed rule reads (alcohol, technology, personal, gift, health ...), so this is the most direct measure of whether the engine is fed correctly: A gave the engine a wrong category on 1 of 65 lines. Every category counts equally, and 13 of the 19 categories have two lines or fewer, so one wrong line in a rare category moves the score by up to 1/19; it measures this data, not the taxonomy.
- **F1 on restricted = true** (A 1.000, C 0.821). Only errors that cross the restricted boundary count, and those decide whether a restricted-item rule can fire at all. C called 5 restricted line(s) unrestricted (the rule then cannot fire: a missed violation) and 2 unrestricted line(s) restricted (material for a false alarm). A category error inside one side of the boundary (gift vs jewelry) leaves this score unchanged and can still change which rule fires.
- **Disposition accuracy** (A 28/28, B 27/28, C 21/28). End to end: inputs and engine together. B feeds perfect categories, so every B error is an input the engine needs beyond the category, or an engine error: B gets RCP-022 wrong (failure case 1). A and C share the engine, so the A-C gap (7 receipts A right and C wrong, 0 the other way) is all classifier.
- **False positives** (A 0/9, C 1/9 of 9 pass). A false alarm on a clean receipt needs a wrong input that triggers a rule. C's: RCP-004 ('Beer battered cod & chips' -> alcohol, correct food_beverage, 'Arnold Palmer' -> other, correct food_beverage, 'Mojito sin alcohol' -> other, correct food_beverage, 'Rum cake slice' -> alcohol, correct food_beverage). A's 0/9 has an upper bound of 33.6%: with 9 clean receipts this data cannot rule out roughly one false alarm in 3 clean receipts.
- **Missed violations** (A 0/16, C 4/16 of 16 flag). A miss is an input the engine needed and did not get. C's: RCP-010 ('Draft IPA 16oz' -> other, correct alcohol); RCP-022 (every category right); RCP-024 ('Marlboro Gold pack' -> other, correct tobacco); RCP-025 ('Schweinebraten mit Knoedel' -> other, correct food_beverage, 'Weisswein 0,2l' -> other, correct alcohol, 'Mineralwasser 0,5l' -> other, correct food_beverage). A's upper bound is 20.6%.
- **Baseline gap.** C is wrong on 16 of 65 lines; on 13 of them no keyword matched (`other`), on 3 a keyword matched something the item is not, and 6 are non-English. Where the keyword baseline does better than the LLM (point estimates): nowhere on these measures. It is free, deterministic and needs no network, which the LLM is not.

## Two failure cases

A LLM gets none of the 28 scored receipts wrong, so case 1 is the one receipt the engine gets wrong when fed perfect categories, and case 2 comes from the held-out set, where the classifier makes more errors. On the scored receipts the classifier gave a wrong category on 1 of 65 lines: RCP-005-L2 'Occupancy tax' -> other, correct lodging (receipt disposition still right). The keyword baseline's errors (above) belong to a system this project replaces.

**1. RCP-022 under B ORACLE. Stage: classification, as the input to the rule logic.** Correct flag with GIFT-04; B gives pass with nothing fired; A gives flag with GIFT-04. Every category is right in B, yet the rule cannot fire: who received the items is stated only in the line text, and gold line labels carry the category alone. A gets it right only because the classifier also returns the stated recipient (RCP-022-L1: government_official, RCP-022-L2: government_official). So the category is not the whole input the engine needs, and a perfect category score would not have caught this. On the held-out set that recipient output is right in 5/5 stated cases and invented on 0/139 lines with none stated. Change: treat the recipient as a scored classifier output with its own test set, and take it from a structured field at submission when one exists, so an anti-corruption exception never rests on one free-text reading.

## Base rate: what if violations were rare (what-if, not measured)

This dataset is 57.1% flag; a real expense stream has a few percent. 0 false flag(s) among 12 non-flag receipts still allows a false-alarm rate of up to 26.5%, so at 1.0%, 3.0%, 10.0% prevalence the share of A's flags that are real (PPV) could fall to 2.9%, 8.5%, 25.0% (both lower bounds; the keyword baseline's point PPV at 3.0% is 12.2%). Before production: per-rule precision on a random sample of real receipts checked by auditors, review-queue workload, drift in confidence bands and category mix, and cost per receipt (the last held-out run cost $0.00033 per receipt).

PPV = sens·p / (sens·p + (1−spec)(1−p)); the range plugs in both lower and both upper CP bounds. A specificity of 100% means no false alarm was *observed* among few negatives; plan with the lower bound.

## What A's scores do and do not mean

A's macro F1 of 0.965 and 28/28 dispositions mean that, in this one run, the classifier gave the engine a wrong category on 1 of 65 scored lines and the system got 0 of 28 dispositions wrong. The engine was written with these receipts and their answers in view, so its share of the score is consistency with the answers, not generalisation; the classifier is the only blind component, and its prompt holds the taxonomy's own examples. It is one run of a sampled model, on n = 28 receipts: the 95% lower bounds are 87.7% for dispositions and 91.7% for line categories. The held-out set is the better estimate of the classifier: 124/144 = 86.1% [79.4%, 91.3%] exact there.
